# DouZero FullAuto ResNet AI 托管

牌局托管方式有两种：浏览器托管在当前页面运行 ONNX 推理，关闭页面后停止；服务器托管由
Java 后台持续读取牌桌快照并提交动作，关闭浏览器后仍会继续；浏览器保持打开时只接收快照用于观战。
服务器托管选择 OpenAI 兼容引擎时
由后台调用已加密保存的 API 配置；选择 DOUZERO 时使用后台内置的合法牌型策略作为决策器。

## 主模型来源

- 主实现：`https://github.com/Vincentzyx/DouZero_For_HLDDZ_FullAuto`
- 固定提交：`6d20491da216c989d23cf2883498758fb78e9f8d`
- 出牌模型：`baselines/resnet/resnet_{landlord,landlord_up,landlord_down}.ckpt`
- 局前模型：`bid_weights.pkl`、`landlord_up_weights.pkl`、`landlord_down_weights.pkl`
- 推理运行时：`onnxruntime-web 1.23.2`，WASM 单线程，按阶段和角色懒加载。
- 浏览器模型：`frontend/public/models/douzero_fullauto/`
- 转换器：`tools/douzero_fullauto/export_onnx.py`

`manifest.json` 固化了来源提交、六个上游权重与 ONNX 的 SHA-256、输入输出契约和
PyTorch/ONNX 数值误差。旧的 LSTM WP 资源已经从生产包移除。

## FullAuto 胜率差异

旧实现只使用三角色 LSTM WP 模型：历史输入为 `5×162`，公开状态输入为地主 `373` 维、
农民 `484` 维；当模型把“不出”排第一时，除立即出完外都会严格服从不出。

FullAuto 的主要差异如下：

1. 使用更大的三角色 ResNet ADP 模型，而不是旧 LSTM WP 权重。
2. 每个候选动作输入完整 `40×54` 矩阵：候选动作、三家剩余牌数、自己手牌、其他未知牌、
   剩余底牌、三家累计出牌和最近 32 次动作。
3. 额外输入 15 维叫抢与加倍先验，保持与目标仓库训练特征一致。
4. 叫地主与抢地主由独立的 `bid` 网络评分，默认阈值分别为 `0.2` 和 `0.4`。
5. 加倍阶段使用地主 ResNet 局前评分或农民专用网络；地主普通加倍阈值 `0.4/0.5`，农民
   普通加倍阈值 `1.0`。
6. 超级加倍同时检查模型评分、服务器道具数量以及目标仓库使用的强牌结构。
7. 出牌阶段在 ResNet 最大评分之外保留 FullAuto 的主动压制思想：检测立即出完、连续控牌
   路径、低收益炸弹和“不出/第二候选”分差，避免模型长期保守不出。

## 决策链

1. 首页保存每个站点用户独立的场次、换桌、领豆和欢乐豆停止阈值。
2. 启动后检查余额和每日补助，再自动进入选定经典场次。
3. 叫抢阶段加载 `bid.onnx`，按当前是叫地主还是抢地主应用对应阈值。
4. 加倍阶段按地主/地主上家/地主下家加载对应局前评分模型，并核对超级加倍卡。
5. 出牌阶段枚举全部合法动作，生成 `z[N,40,54]` 与 `x[N,15]`，批量取得 ADP 评分。
6. 决策器依次处理立即出完、连续控牌路径、低分炸弹、主动压制和模型最大评分。
7. 结算后刷新余额；开启自动换桌时继续下一桌，否则在原桌准备。

## 状态完整性

- 服务端保留每局最近 256 条动作，浏览器核对“三家初始牌数 − 当前剩余牌数”和历史实际
  出牌数。
- 公开牌历史完整时运行 FullAuto ResNet；历史缺失时改用确定性的保牌型策略，避免向模型
  输入互相矛盾的剩余牌与历史牌。
- 地主打出与底牌同点数的牌后，ResNet 的“剩余底牌”特征会同步扣除，和目标仓库环境一致。

## 运行边界

- FullAuto ResNet 仅用于经典斗地主。
- 同一浏览器一次只提交一个 AI 动作，并以牌桌快照指纹去重。
- 模型在浏览器本地推理，手牌不会提交到额外的 AI 服务。
